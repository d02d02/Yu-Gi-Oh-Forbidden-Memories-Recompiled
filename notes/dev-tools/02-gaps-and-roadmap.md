## Design: `situation()`, a `goto` for board positions (asked 2026-10-13)
Goal: "monsters on slots X, after attack Y, camera angle Z, frame N after the hit" as ONE declarative request, resolved and cached,
instead of clicking. Same idea as `Game.goto(target, opponent, deck)`: name the destination, the tool finds the path.

Spec (JSON/dict, hashed for the cache key together with build id + settings + mods):
`{"opponent": 1, "hand": [ids], "opp_hand": [ids], "turns": [{"play": [[slot, "up|down", star]], "fuse": [[slots]], "attack": [column, target]}...],
  "camera": {"turn": deg | "near"}, "until": "<predicate>", "shots": {"every": 2, "count": 30}, "check": "<pixel/RAM assertion>"}`

Resolution, cheapest first:
1. **Tier A (Python only, works today):** compile the spec into `arrange_deck` + `play_card/fuse/attack/end_turn` on `Game`
   (verified: monster up, trap face-down, field spell, all deterministic, ~6-11 s). Save a state at the end -> state bank
   keyed by spec hash; later runs `load` it and only do the camera + the frames that matter. Opponent: `arrange_deck(1, ...)`; its
   plays come from the AI, deterministic for a given seed (RNG is in states), so a seeded opening reproduces; verify with `hash`.
2. **Tier B (poke the board, skip the playing):** write card records/zone flags directly (what test-scenes does with
   `func_80024D34` + `Duel_ApplyCardObjectFlags`), exact slots/positions/face-state/LP for BOTH sides. Needs one small
   addition: either grow test-scenes (hand, spells/traps, position, LP, whose turn) or a client helper that pokes the records
   (`duel()` already decodes them: `D_801A7AD8` records, `D_800E9FF0` sides). Use when the AI would not cooperate.
3. **Tier C (engine/mod `jump` target, like MachineGun's):** a `jump duel_scene <spec>` handled in the port, no title navigation.
   Only if A+B prove too slow or brittle; it is an upstream-facing change.

**Status 2026-10-13: camera control and the attack-phase predicate are built and committed (`origin/dev` 552fddfec).**
Findings (evidence in `evidence/2026-10-13/`):
- Camera = `D_800F2848` (s16 distance at +0, s16 angle at +2; 4096-unit turn, 1024 = usual view, distance 600 usual, 334 on the field phase). **Poking it, or the GsRVIEW2 inside it, changes the numbers but NOT the picture** (0.0% diff): only `ViewState_ApplyOrbit` re-applies it, which the game calls only during its own tweens. Every game camera move (placing a card, end turn, attack) tweens to an absolute target, so a hand-phase L1/R1 turn is lost (1024 -> 2044 -> back to 1024 on placing).
- Solution: `mods/camera-pin` (code mod). Holds angle/distance in the scene phases of a phase mask and calls ApplyOrbit. Runtime control is a **pad-2 mailbox** (`0x4000|angle`, `0x8000|distance`, `0x2000` clear), because **mod setting values are part of a save state's signature** (`Mods_Signature`: enabled mods + manifest + code hash + every runtime option): one state cannot be loaded with different mod settings. Helper `rigkit.camera_pin(g, angle, distance)`.
- Attack phase: scene phase 9 (`battle`) has a sub-step machine in the low nibble of `D_8009B174`; monster-vs-monster ran 225 vblanks, identical on repeat: sub-step 1 (camera tween 334->600, 12 vb) | 2 @12 | 3 @13-30 | 4 @54 | 7 @103 | 10 @148 | 6 @206 | 11 @208 | field phase 5 @225. Predicate: `rigkit.battle_step(g)`, `wait_battle_step(g, n)`.
- Scenario: `rigkit.py attack --deck 374 --camera 2048,400 --at 2,4,7,10 --scale 2` = state saved right before the battle (1x), loaded at any scale, camera pinned, shots at the first vblank of each sub-step; A/A identical.
- **What the battle shows (filmstrip, `attack --every 12`, 3D and 2D monsters on, 2026-10-13):** vb 0-~30 (steps 1-2) the FIELD with the attacker (3D model / 2D cutout: the only window where a mod's on-field art is visible during the attack; at vb 24 the 2D build also shows the battle cards swinging in edge-on); steps 3-10 (vb 30-~225) the full-screen CARD presentation (flash at 4 and 8, fire when a monster is destroyed at 10), no field, camera irrelevant; ~vb 228+ the field fades back, top-down field phase. Timeline same for 3D and 2D (2D 1 vb earlier). To validate a mod's on-field attack look at vb 0-30 and after ~228; the camera pin only matters there.
- **3D Monsters `battle` option on** (`--settings mod.3d-monsters=1 mod.2d-monsters=0 mod.3d-monsters.battle=1`): the two models stand on the big attack cards through steps 3-11 (vb ~30-225), cards dimmed, with the flashes (4, 8) and fire (10) drawn over them; so for THAT mod feature the validation window is vb 30-225, per step (shoot at `--at 3,4,7,8,10`), not vb 0-30. Only the 3D models style has it (2D Monsters has no attack-card setting: its look is the vb 0-30 / post-228 field view). Evidence: `attack-filmstrip-3d-battle-option-1x.png`.
- Still open: names/meaning of each sub-step (read `duel_scene_battle.c` cases 1-11); the 2D-monsters mod's own on-field attack happens in these steps with `mod.3d-monsters`/`2d-monsters` on (tested here with them off); poking records for odd slots (Tier B); pixel-count helpers.

Missing pieces to build (each small; camera and phase predicate DONE, see status above):
- **Camera control:** L1/R1 rotates the battle camera (`progress.md`); find the camera state address (`scene_measure.py trace --camera turn:<deg>|near|near-half` already sets it: reuse its poke) and expose `g.camera(turn=deg)`.
- **Phase predicates:** `wait_until(lambda g: attack_phase(g) == HIT)`; find the attack animation phase byte (the `phase()`/`DuelScene` state handler index plus a frame counter) so shots are keyed to "N vblanks after the hit", not wall time. Until found, use `step(k)` counts from `attack()` (deterministic).
- **Pixel assertions:** `px.count(png, mask|region|colour)`, `px.diff(a, b)`, golden store per build; exact counts are meaningful because runs are bit-identical (measured 0.0000% diff, main WIP vs upstream, same scenario).
- **2D-monsters-attacking-each-other:** needs both sides' monsters placed and the attack animation reached: Tier A usually (play, end turn, AI plays, attack); Tier B for odd slots.
- Put specs in `tests/pc/situations/*.json` (committable, no disc data); states stay in git-ignored `tmp/pc/states/`.

Build order: `camera()` + `phase` predicate (explore, ~1 session) -> Tier A compiler + state bank -> pixel helpers -> Tier B pokes -> one real spec for the 2D-monsters mod as the acceptance test.
