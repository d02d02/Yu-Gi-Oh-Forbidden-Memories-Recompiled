# Job vip-e9-timemap

## Goal
The render-side sampler reads a per-act time map (Studio need E9): an authored list of `[clip_frame, row_frame]` points that replaces the automatic mapping from the disc row's frame to the clip's time, for the acts that have one. Data only, gated: an act with no map plays exactly as before (byte-identical), including `strike_warp` and the BLS warp. The recipe key `acts.<act>.timemap` (S6, `tools/hd-models/studio/timemap.py`) must reach the package so the Studio's edits take effect.

## Facts (pasted; read other code only by `grep -n` then at most 40 lines)
- Time map = list of `[clip_frame, row_frame]`, both strictly increasing, first point `[0,0]`, last `[clip_frames, row_length]`. Python reference semantics, `studio/timemap.py:row_to_clip`: clamp `row_frame` to the first/last point's row, else find the segment and interpolate linearly: `c0 + (row - r0) * (c1 - c0) / (r1 - r0)`. The C function must give the same numbers (test both ways with the same cases).
- `src/pc/render/native_anim.c`: `static float strike_warp(const NativeMesh *mesh, const NativeClip *c, float frame, int contact, int length)` maps a row frame to clip time in seconds (returns -1 when it cannot); `NativeAnim_Choose(...)` is the director; for attack rows it calls `strike_warp(mesh, c, (float)anim_frame_16 / 16.0f, d->info.contact_frame, d->info.anim_length)` (see ~line 195). Clip time in seconds = clip frame / `c->fps`. For non-attack rows the clip runs linearly over the row's length. A map applies to whichever act it is for, before those paths: if the act has a map, `t = NativeAnim_TimeMapClip(points, count, row_frame) / c->fps` and the other warps are skipped.
- Data in the package: `model.json` gets `"timemaps": [{"act": "attack", "points": [[0,0],[20,10],[60,40]]}]`, parsed in `src/pc/render/native_registry.c` exactly like `"shots"` (`grep -n "package_shots" src/pc/render/native_registry.c`: copy its structure, its error `note(...)` style and limits; at most 8 maps, 16 points each; reject non-increasing points with a `note`). Store in `NativeMesh` (`src/pc/render/native_model.h`, next to `shots`/`shot_count`).
- Pure function, declared in `native_anim.h`: `float NativeAnim_TimeMapClip(const float (*points)[2], int count, float row_frame)` (points are `{clip, row}`), unit-tested in `tests/pc/native_anim_test.c` (add cases; keep existing): endpoints, clamping both sides, midpoint of a two-segment map, a count of 2 default map equals linear, matches the Python numbers for `[[0,0],[10,20],[30,40]]` at rows 0, 10, 20, 30, 40, 50 -> 0, 5, 10, 20, 30, 30.
- Python: the Studio build turns the recipe into a package (`tools/hd-models/studio/build.py`, `grep -n "shots" tools/hd-models/studio/*.py tools/hd-models/native_convert.py` to see how the recipe key `shots` reaches `model.json`; mirror that for `acts.<act>.timemap` -> `timemaps`). Test: `tools/hd-models/tests/test_timemap_build.py` (stdlib unittest, run `python tools/hd-models/tests/test_timemap_build.py`): a recipe with `acts.attack.timemap` yields a package `model.json` with the matching `timemaps`, a recipe without yields no `timemaps` key (byte-identical to before), a non-monotonic map is rejected by `timemap.check_monotonic` before the build.
- Build: `bash verify.sh build` (about 35 s), C test: `bash verify.sh c`, Python: `bash verify.sh py`. `verify.sh` is protected. Run with RALPH_MODEL=vip. Python is `python`. LF endings. Do not push.
