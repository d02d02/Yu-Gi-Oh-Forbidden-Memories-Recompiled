# Job vip-e5-overlay

## Goal
Editor overlays drawn by the game's native model pass (Studio needs E5 and E6): thin 3D lines for the model's bounding box, a ground grid under it, and the skeleton's bones, switched on and off over the control channel, plus a text read-back of the last drawn model's bounds. Gated: all overlays off (the default) means the pass draws exactly as before (same pixels, same hashes). Phase 1 = make it work, small.

## Facts (pasted; read other code only by `grep -n` then at most 40 lines, except `native_draw` below)
- The native model pass is in `src/pc/render/gl_picture.c`: `static void native_draw(unsigned id)` (~line 2342 to ~2480, read it whole once) draws one `NativeDraw` (`native_ring[id]`, see `src/pc/render/native_model.h`: the part matrices, `mesh` with positions in model space, skin/joints/weights, clips) into the model's own framebuffer with `glDrawElements(GL_TRIANGLES, ...)` (~line 2471) and a GLSL program. Overlays are lines drawn into the same framebuffer right after that draw, with the same view/projection and model transform that the triangles use, and with depth test on. Use GL_LINES with a tiny second program or the existing one with a flat colour (your choice; keep it simple), colours: bbox yellow, grid grey, bones green.
- Pure, testable part in NEW files `src/pc/render/native_overlay.c` and `native_overlay.h` (no GL, no game memory): flags `bbox`, `grid`, `bones` (all 0 at start) with getters `NativeOverlay_Flags()`, and `int NativeOverlay_Command(const char *line, char *reply, size_t n)` parsing `ov bbox on|off`, `ov grid on|off`, `ov bones on|off`, `ov off` (all off), `ov get` (reply `ok ov bbox=0 grid=1 bones=0`); errors for anything else. Same return and reply convention as `NativeAnim_Command` in `native_anim.c` (`grep -n "NativeAnim_Command" src/pc/debug/control.c` shows how control.c forwards `anim ...`; forward lines starting with `ov ` the same way, forwarding only). Also pure here: `void NativeOverlay_BoxLines(const float min[3], const float max[3], float out[12][2][3])` (the 12 edges of an axis box), `int NativeOverlay_GridLines(const float min[3], const float max[3], int cells, float out[][2][3], int cap)` (a square grid of `cells` x `cells` lines on the box's lowest plane, at most `cap` segments, returns the count); both unit-tested in `tests/pc/native_overlay_test.c` (a unit box, counts, endpoints on the box).
- Read-back (E6): the last model the pass drew leaves its bounds: `NativeOverlay_Record(const float min[3], const float max[3])` (called from native_draw with the mesh's model-space bounds, which `NativeMesh` may already hold: `grep -n "bound\|min\[\|extent" src/pc/render/native_model.h`; if not, compute once per mesh from the vertex positions) and `ov bounds` replies `ok ov min=x,y,z max=x,y,z lowest=y` (`lowest` = the largest y because the game's y is down) or `err ov: nothing drawn`. Unit-tested.
- Bones: the mesh's bone count is `mesh->bones`; clip poses are `frames x bones x 7` (t[3], q[4] xyzw) local to the parent; the skinning matrices native_draw already builds for the shader give each bone's world position as the translation of its matrix; draw a line from each bone to its parent (`grep -n "parent" src/pc/render/native_model.h` for the parent array). If the parent array is not in NativeMesh, draw a short cross at each bone instead and say so in the final message.
- Client: `tools/pc/yfm_control.py`, class `Game`: add `ov_bbox(on)`, `ov_grid(on)`, `ov_bones(on)`, `ov_off()`, `ov_get()` (dict of 0/1), `ov_bounds()` (dict or None), modelled on the `anim_*` methods; test `tools/pc/tests/test_yfm_overlay.py` with a fake socket like `tools/pc/tests/test_yfm_anim.py`.
- The new .c file must be in the game build: `grep -n "native_anim.c" -r CMakeLists.txt tools/pc/build_game32.py` shows where native_anim.c is listed; add native_overlay.c beside it.
- Build: `bash verify.sh build` (about 35 s, output tmp/pc/vip-e5-overlay-build/memories-pc.exe). C test: `bash verify.sh c`. Python: `bash verify.sh py`. `verify.sh` is protected. Run with RALPH_MODEL=vip. Python is `python`. LF endings. Do not push.
