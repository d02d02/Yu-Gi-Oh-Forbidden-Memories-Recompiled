## Precise geometry (PGXP)

### Measurement framework (2026-09-28)
Why: levels 1/2 were justified by theory only; "no distortion seen" is by eye. The user will not write the PR or start model work on unmeasured claims; the framework also serves 7c (HD textures: same frame, two settings, a number).
- **Level 1 (Textures):** console interpolates UVs affinely in screen space; level 1 interpolates `uv/w`, `1/w` (`gl_picture.c`, flag 32). Vertex stays on its console pixel; error grows with depth spread and triangle size. Claims: visible on large, steeply tilted textured polygons near the camera (field floor, battle close-up, Library model view); invisible on small triangles (3D Monsters figures); no change at 1x and 2D screens.
- **Level 2 (Textures and positions):** GTE rounds each vertex to a whole console pixel (up to N/2 screen px at Nx). Claims: temporal ("wobble" in slow camera/model motion), stronger at high resolution and on small models; risk = gaps between model parts (#83), which `draw_id` (7b) should remove.
- **Measurements:** M1 texture displacement per triangle (screen px); M2 mixed-precision triangles; M3 image diff Off vs level 1 with controls; M4 `|precise - rounded|` per vertex; M5 seam spread/cracks (measurement build with clamp 2 = "before"); M6 blind A/B of a slow pan; M7 same script on Unchiga's machine.
- **Review lessons of the first draft:** controls are needed for a noise floor (same setting twice = 0 px; 1x and 2D screens = 0; software picture identical across levels); fix thresholds before looking; report screen pixels, not texel error; sample barycentric points instead of an analytic formula; vertices have no identity across frames (use amplitude + blind A/B); level-2 amplitude is measurable today (precise positions are computed at level 1, only their use is gated); measure gaps geometrically (same draw, same rounded word must land equal); a driver bug needs a single runnable script for others; Unchiga's field-edge suspect = mixed triangles (flag 32 needs all three depths; a clamped vertex makes its triangle affine beside perspective neighbours); `MEMORIES_DUMP_FRAME` writes one frame then `exit(0)` (add a range); dumps are at internal resolution (`MEMORIES_SCALE_AT=<frame>:<scale>` scripts it); PS1 games often subdivide big polygons (floor is not subdivided here).
- **Pipeline:** scenes from the test-scenes mod (not save states), controls first, runner per scene x level x scale writes dumps/trace; analysis applies thresholds. Measurement code stays on its own branch, never in a PGXP PR.

### Trace results (2026-09-28)

Scene `field`, Textures: 2905 textured triangles (2883 perspective, 16 mixed, 6 affine); 2x: M1 max/median/95th 4.62/0.01/0.40 px; >= 2 px 42 triangles (<= 17.2% frame), 1-2 px 65 (<= 12.4%); 4x max 9.24, >= 2 px 107 (<= 29.6%). ### 7a. Warped textures: the Video option (2026-09-27)
Cause: GTE rounds each vertex to a whole console pixel and keeps no depth, bending textures on tilted surfaces. The fix (`src/pc/compat/pgxp.c`, HMD polygon drivers in `src/pc/overrides/model_polygon_drivers.c`) existed but `SET_PGXP` was clamped to 0 everywhere (settings, `MEMORIES_PGXP`, runtime) with no menu entry. First pass wrongly offered levels 0-2: `git log` of `notes/pc-build.md` showed #83's removed comment "positions too are experimental, they open gaps in the small monster models". `snap_seams` (`libgpu.c:386`) finds a seam only by two vertices rounding to the same screen word this frame, so on a ~32 px model unrelated parts collide and a triangle distorts. Corrected: clamp 0-1, Video > Precise geometry Off/Textures, greyed below Internal 2x or without OpenGL 3 (like HD text). One call path (`func_800540B4` -> `GsSortUnit` -> HMD polygon drivers) covers field figures, animated battle and the Library model view. Checked: smoke suite byte-exact (incl. `options`), `MEMORIES_TRACE=frames` shows ~300 precise vertex words with pgxp=1, live Off vs Textures no artifacts; `tests/pc/settings_test.c` updated (CI runs it; no zlib/libpng for local CMake). Lesson: check a file's `git log`, not only its current text.

### 7b-bug. Arena corruption found live (2026-09-27)
Symptom (user live, nothing of mine caught it): thin lines flickering from the left/top edge, at Textures and level 2, gone with Off. ## 2D Monsters mod (`mods/2d-monsters/`, 2026-09-29)
Alternative to 3D Monsters: an enlarged camera-facing cutout of the card's own art (`WA_MRG.MRG` 102x96 record) floats over its card. Off by default, `"conflicts": ["3d-monsters"]` (same `SOFT_GPU_BANKS` range). Reuses 3D Monsters' LRU bank cache, `duel_field_up()` gating, one `RotTransPers` per corner pair (same projection as `func_80015EF4`). Cherry-picked from `claude/2d-art-replace-3d-models-bbpme7`; clean copy `feat/2d-monsters-mod`.
Three bugs, found live (screens too big, opponent side clipped, then cropped flat across the bottom):
1. `draw_frame()` ran `fit_height()` (calibrates world height by projecting two points) before `GsSetRefView2`/`SetGeomScreen`/`SetGeomOffset`: moved the camera setup first.
2. Log `fit_height: target 40 px, got 66 px, height 128 after 6 attempt(s)`: `HEIGHT_SMALLEST = 128` was copied from 3D Monsters' `SCALE_SMALLEST = 0x100`, a fixed-point scale fraction (4096 = 100%), not a world height; the real answer is ~60-80, the loop pinned at the floor (65% too big, "a wall off the field's edge"). Now 16; `DEFAULT_PIXELS` 40 -> 32 (a persisted setting still wins over a new default). Fixed log: `got 40 px, height 189 after 3 attempt(s)`.
3. Cutouts cropped where each zone's field-card token sits: depth scale (3D Monsters divides raw depth by 4 before sorting, `at = nearest / 4 - tunable("depth", DEPTH_STEPS)`, `field_models.c:677`) AND the wrong table: `D_800E9D90[0]` is a 4-slot table (`table->length` 2), every cutout saturated at index 3 (raw 126 and 171 both gave 3). **Lessons:** each bug was a plausible assumption copied by analogy from the sibling mod (step order, a constant of another kind, a borrowed resource named by a comment): analogy gives a candidate fast but read the reference code for the matching situation, and close each out with a live numeric log checked against a falsifiable prediction (screenshots could not tell the causes apart).

Reusing zone thumbnails failed (they are cropped details, not full art).
